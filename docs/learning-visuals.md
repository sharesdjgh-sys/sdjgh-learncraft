# 답변 내 학습 시각 자료

## 답변 원칙

매 답변에서 시각 자료가 학습에 필요한지 판단하고, 위치·형태·구조·변화·비교·과정·음높이 등 시각화가 이해에 필요한 내용에는 **별도 요청 없이 반드시 포함**한다. 학생이 그림이나 지도를 요청해도 지원 도구를 사용한다. 단순한 뜻풀이처럼 도움이 되지 않는 경우만 생략한다.

1. 정확한 수치·기호가 필요한 내용은 기존 그래프·도형·표·지도·악보를 사용한다.
2. 실제 작품이나 사물 사진이 필요하면 Wikimedia Commons를 검색한다.
3. 기존 도구와 참고 이미지로 충분히 설명하기 어렵고 그림이 꼭 필요하면 Nano Banana로 학습용 개념 그림을 생성한다.
4. 그림 앞뒤에 관찰할 부분과 핵심 개념을 설명한다. 생성 그림을 실제 작품·실측 자료·공식 정답으로 제시하지 않는다.

이 원칙은 튜터 시스템 프롬프트에 적용한다. 모델의 판단·출력에 의존하므로 모든 질문에 대한 시각 자료 포함을 프로그램이 강제하거나 내용의 정확성을 보증하는 것은 아니다. 생성 도구 실패나 한도 도달 시 표·도식 등 가능한 대체 자료를 제공하도록 지시한다.

## 구성

- Mermaid: 구조화된 관계도와 세로 연표. 원시 Mermaid 문법은 받지 않으며, 앱이 검증된 노드·연결로 문법을 생성한다.
- d3-geo + topojson-client: Natural Earth 기반 World Atlas 2.0.2 지도.
- world-atlas: 지도 데이터 원본 패키지. 실제 배포 파일은 public/maps/countries-50m.json.
- VexFlow: 높은음자리표/낮은음자리표, 2/4·3/4·4/4·6/8박자, 최대 4마디의 음표·쉼표·화음.
- entities: 라벨의 숫자·이름 문자 코드를 일반 문자로 복원한다. 줄바꿈은 LF로 정규화하고 Mermaid SVG에서 여러 tspan으로 나뉜 문자 코드는 글자 노드만 수정해 복원한다. SVG 태그나 속성을 문자열로 디코딩하지 않는다.
- DOMPurify: Mermaid 결과 SVG 정리. 외부 이미지·링크·foreignObject를 제외한다.
- Wikimedia Commons: 서버의 search_learning_images 도구로 검색하고, /api/learning-media에서 파일 메타데이터를 재확인한다.
- Gemini Nano Banana: generate_learning_illustration 도구로 gemini-3.1-flash-image를 호출하여 학습용 개념 그림을 만든다.
- 기존 learncraft-graph, learncraft-figure, Markdown 표는 유지한다.

지도·관계도·악보 라이브러리와 Commons 검색은 별도 유료 시각화 API를 사용하지 않는다. Nano Banana는 기존 GEMINI_API_KEY를 사용하지만 **이미지 생성 API 비용이 추가**된다. 이미지 저장 비용도 발생할 수 있다. 데이터베이스 마이그레이션은 필요하지 않다.
지도·관계도·악보 렌더링 라이브러리는 해당 자료가 필요할 때 불러온다.

## 응답 형식

AI는 필요한 설명 위치에 learncraft-visual 코드 블록과 JSON을 출력한다.
지원 kind: flow, timeline, map, music, image, generated-image.
전체 규격과 예시는 src/features/tutor/visual-prompt.ts, 검증은 src/lib/learning-visual.ts에 있다.
같은 Markdown 컴포넌트를 사용하는 대화·북마크에서 동일하게 표시한다.

## 자료의 신뢰성과 제한

- 실제 지도 바탕은 데이터로 그린다. AI가 지정하는 강조·좌표·경로의 사실성까지 자동 검증하는 것은 아니다.
- 일반화된 바탕 지도는 역사적 국경이나 최신 영토 판단 자료가 아니다. 기후 분포·역사 지도는 별도 출처가 필요하다.
- 지도 focus: world, eastAsia, europe, africa, americas, oceania. countries는 ISO 숫자 코드 3자리.
- 악보의 마디 길이는 박자와 대조한다. 점음표·잇단음표·조표·오디오 재생은 아직 지원하지 않는다.
- 이미지 검색 결과를 모델에 제공하지만 이미지 픽셀을 자동으로 모델에 재입력하지 않는다. 작품 일치 여부는 메타데이터에 근거하며 세부를 직접 관찰했다고 주장하지 않도록 지시한다.
- 이미지별 라이선스와 제작자, 원문 링크를 표시한다. 현재 PD/CC0/CC BY/CC BY-SA 자료만 허용한다.
- 도구는 한 답변당 최대 2회 검색한다. 최대 4회 모델 단계 중 마지막은 도구 호출 없이 답변한다.
- 튜터 모델의 도구 사용을 포함한 합산 토큰은 기존 onEnd usage로 기록한다. 이미지 모델의 토큰은 별도 서버 로그로 남기며 텍스트 모델 단가로 계산하지 않는다.
- Commons 외부 요청은 8초 제한, 동일 요청은 프로세스 내에서 1시간 캐시하고 중복 요청을 합친다. 캐시는 최대 200개다. HTTP 429 응답 시 Retry-After에 따라 최소 1분 동안 새 요청을 중지한다.
- 외부 이미지 검색 실패는 본문 설명을 중단시키지 않는다. 자료 형식 오류는 안내로 대체한다.

## Nano Banana 설정·저장

- GEMINI_IMAGE_MODEL_ID=gemini-3.1-flash-image (기본값)
- GEMINI_IMAGE_ENABLED=true (기본값, false면 이미지 생성만 비활성화)
- GEMINI_API_KEY: 해당 이미지 모델을 사용할 수 있는 기존 Gemini 프로젝트 키. Nano Banana에는 Blob이나 별도 저장소 설정이 필요하지 않다.
- 답변당·계정당 별도의 이미지 생성 횟수 제한을 두지 않는다. 필요한 그림을 추가 생성할 수 있다. 기존 일반 질문 사용량과 모델 단계·실행 시간 제한은 유지한다.
- 이미지 API 요청은 75초, 생성·압축 전체는 140초로 제한한다. 한 번 생성한 이미지를 압축 후 바로 표시하며 별도 AI 검수나 수정 재생성은 하지 않는다. 생성·압축 실패 시 본문을 유지하고 재요청을 안내한다. 튜터 경로의 maxDuration은 180초이다.
- 생성 그림은 1K와 High thinking으로 요청한다. 화면 비율은 4:3(기본) 또는 1:1만 허용하며 서버에서도 검증한다. 원래 크기를 확대하지 않고, 이전 2K 이미지와의 호환을 위해 최대 3072px까지 보존한 WebP(품질 94→90→86, 크기 초과 시에만 다음 품질 시도)로 변환하여 인증된 답변 스트림에 직접 삽입한다. 서버가 만든 data:image/webp;base64만 허용하며 외부 URL·SVG는 허용하지 않는다. 이미지 한 장의 전송 데이터는 1MB 이하로 검증한다.
- 답변 모델에는 생성 예약 여부(scheduled:true)와 제목·설명만 즉시 반환한다. 이미지 바이트는 답변 출력 토큰이나 후속 질문의 대화 맥락에 포함하지 않는다.
- 북마크는 이미지 데이터를 답변과 함께 기존 데이터베이스에 저장한다. 답변 저장 크기 검증은 4백만 문자이다. 브라우저 탭의 임시 저장 한도를 초과하면 현재 대화는 계속 사용할 수 있지만 새로고침 복원용 캐시는 생략한다.
- 새 그림에는 생성 설계의 핵심 개념 설명을 `textContent`로 함께 보낸다. 그림 아래의 ‘그림의 글·핵심 개념 보기’는 기본 접힘 상태이며 제목·개념 설명·관계를 일반 텍스트로 펼쳐 보여준다. 이미지 OCR이 아니라 생성에 사용한 설명이므로 그림에서 축약·의역된 실제 문구와는 다를 수 있다. 글자의 이미지 렌더링 깨짐 없이 읽을 수 있지만 AI가 작성한 내용의 오탈자·정확성을 보증하지 않는다. 북마크와 복사에도 텍스트를 보존하며, 해당 자료가 없는 이전 이미지는 폴딩을 표시하지 않는다.
- 이전 버전에서 저장한 이미지의 /api/learning-images/[id] 경로는 읽기 호환용으로 유지한다. 새 이미지 생성은 이 경로나 Blob에 의존하지 않는다.
- 질문 원문이나 첨부 사진을 이미지 생성에 자동 전달하지 않는다. 튜터가 만든 개념 그림용 지시문만 전달한다. 지시문에는 개인정보를 넣지 않도록 지시한다.
- 그림에 “LearnCraft AI 생성 그림 · 학습용 예시”와 세부 표현의 한계를 표시한다. 생성 이미지를 실제 작품 원본·검증된 지도·공식 정답이라고 주장하지 않는다. 명시적 그림 요청이면 과목과 관계없이 Nano Banana를 사용하고 정확한 식·조건은 본문에 설명한다.
- 그림 설계의 학습 목표·부분별 설명·연결 관계는 작화용 맥락이며 이미지에 그대로 쓰는 문구가 아니다. 실제 이미지에는 핵심·기본 개념 2~4개, 짧은 제목·라벨, 필요할 때 개념별 짧은 설명 한 줄을 담고 큰 장면·구조·비교 그림과 충분한 여백을 중심으로 구성한다. 긴 정의·유도 과정·예외·부가 예시·심화 내용은 본문에서 제공하며, 이미지에는 기본 개념을 이해할 최소 설명만 남긴다. 빽빽한 문단·설명 카드나 단순한 이름·장식 아이콘 나열을 지양한다.
- 학습 대화의 실패한 그림에는 `다시 생성` 버튼을 제공한다. 원래 설계가 있으면 그대로 재사용하고, 이전 저장 데이터는 제목·설명·핵심 개념으로 설계를 복원한다. 재생성은 해당 그림만 교체하며 본문과 다른 그림은 유지한다. 생성 중 중복 클릭을 막고 화면을 떠나면 요청을 취소한다. 로그인·학교 단원 접근·질문 사용 한도를 확인하며 성공 시 질문 1회를 사용하고 실패 시 예약 횟수를 반환한다. 별도 검수는 하지 않는다.
- 별도 시각 검수 모델을 호출하지 않는다. 생성 프롬프트에 대상과 명칭의 일치, 인과관계·방향·순서의 보존, 필수 조건·부정어 유지, 근거 없는 수치·공식 생략을 명시한다. 핵심 개념 2~4개와 짧은 라벨 중심으로 그리며 자세한 글은 본문과 접기 영역에서 제공한다. 프롬프트만으로 사실 정확성을 보증하지는 않는다.
- 생성 그림 자체를 클릭·터치하면 확대하고 Escape 또는 닫기 버튼으로 돌아온다. 키보드로 그림에 초점을 맞춘 뒤 Enter·Space로도 확대할 수 있다. 확대 화면의 이미지 저장 버튼은 원본 해상도를 유지한 JPG를 그림 제목의 파일명으로 내려받는다. 투명 영역은 흰색 배경으로 채운다. 별도 확대 버튼과 그 버튼용 여백은 두지 않는다.
- 이미지 생성 사용량은 learning_image_usage 서버 로그에 모델명과 토큰 수만 기록한다. 질문·생성 지시문·이미지 데이터는 로그에 넣지 않는다. 북마크하지 않은 생성 그림은 서버에 보관하지 않는다.
- 이미지 실패는 `learning_image_failure` 서버 로그로 남긴다. 이미지 ID, 생성 모델, 실패 직전 단계, 경과 시간, 고정 오류 코드, HTTP 상태만 기록하며 요청·응답 원문은 기록하지 않는다. 화면에는 원인별 안내를 표시한다. 기존 저장 데이터의 검수 단계·오류 코드 렌더링은 호환성을 위해 유지한다. PWA 설치 배너 및 미사용 preload 경고는 이미지 API 실패 원인을 담고 있지 않다.
- 관리자 대시보드의 예상 비용은 현재 텍스트 API 비용이다. 이미지 비용을 합산하지 않으며 이를 화면에 표시한다. 실제 이미지 비용은 Gemini 프로젝트 사용량·청구에서 확인한다. API 실패·중단 시 사용량 정보가 반환되지 않을 수 있다.
- 공식 모델/API 설명: https://ai.google.dev/gemini-api/docs/generate-content/image-generation

## 실제 작업 단계 표시

- 튜터 화면은 `Accept: application/x-ndjson`으로 진행 상태와 답변 텍스트를 분리해서 받는다. 기존 일반 텍스트 응답 및 데모 응답도 지원한다.
- 질문 확인, 답변 작성, 자료 검색, 그림 생성, 이미지 정리, 대체 설명, 연결 재시도를 실제 실행 콜백에 맞춰 표시한다. 시간을 기준으로 단계를 추측하지 않는다.
- 모델의 다음 텍스트를 기다리는 중에도 진행 상태를 즉시 전송한다. 여러 도구가 실행 중이면 종료되지 않은 작업을 표시한다.
- 진행 문구는 대화 본문·복사·북마크에 포함하지 않는다. 본문이 일부 나온 뒤에도 현재 답변 상단에 작업 상태를 표시한다.
- `npm run test:tutor-progress`: 즉시 상태 전송, 병렬 작업, UTF-8/메시지 경계 분할, 본문 보존, 완료·취소·오류를 검증한다.

## 명시적인 생성 이미지 요청

- “인포그래픽”, “그림으로 설명해 줘”, “그림을 그려 줘” 등은 서버에서 생성 이미지 요청으로 분류한다. 용어 정의, 첨부 그림 해석, 그림 생략, 순서도만 요청하는 경우는 구분한다.
- 이 요청은 첫 모델 단계에서 `generate_learning_illustration`을 지정 호출하며, 후속 단계에서도 이미지 생성 도구만 허용한다. 여러 그림이 필요하면 추가 생성할 수 있으며 기존 마지막 모델 단계에서는 도구를 끄고 설명을 마무리한다. 일반 도식 우선 지침보다 우선한다.
- 서버가 생성·압축을 마친 이미지 블록만 전송한다. 모델이 대신 작성한 코드 블록·이미지 링크는 최종 설명에서 제거한다. 이미지가 없으면 이미 제공한 본문을 유지하고 서버의 실패 안내를 추가한다. 모델에는 생성 진행 중임을 명시하며 완료됐거나 그림을 보았다고 주장하지 않도록 지시한다.
- 비활성화/키 미설정 시에는 질문 사용량을 예약하기 전에 이미지 생성 불가를 안내한다. 명시적 생성 요청의 실패는 도식으로 대체하지 않는다.
- `npm run test:image-intent`로 요청 분류, 호출 강제, 대체 도식 차단, 실패 안내를 검증한다.

## 본문 먼저, 생성 이미지 나중에 표시

- 이미지 도구는 생성 작업을 예약하고 즉시 반환한다. 텍스트 모델은 이미지 생성·압축를 기다리지 않고 핵심 설명을 작성한다.
- 이미지 작업은 같은 응답 스트림이 끝날 때까지 추적·대기한다. 서버 응답이 닫힌 뒤 실행하는 작업이나 별도 저장소가 아니다.
- 본문은 먼저 스트리밍하고 도구가 반환한 placementMarker 위치에 4:3 또는 1:1 그림 공간을 확보한다. 생성·압축 완료 이벤트가 해당 자리만 실제 그림으로 교체한다. 표식 누락 시에만 본문 끝에 자리를 확보한다. 빠른 그림이 느린 그림을 기다리지 않으며, 동일 설계의 중복 예약은 합친다.
- 명시적 그림 요청에서도 본문 전체를 버퍼링하지 않는다. 줄 단위 필터로 모델이 쓴 대체 도식 코드 블록과 이미지 링크를 제거하면서 설명을 전달한다.
- 이미지 대기 중에는 해당 그림 자리에서 읽기 안내와 개별 생성·압축 상태를 표시한다. 완료되면 대기 안내가 사라지고 실제 이미지가 나타난다.
- 실패 시 본문은 유지하고 해당 그림 자리에 실패 안내를 표시한다. 스트림 취소·오류 시 이미지 작업에도 취소 신호를 전달한다.
- `npm run test:deferred-images`: 본문 선출력, 이미지 지연 삽입, 여러 이미지의 완료 순서, 중복 방지, 실패 시 본문 보존, 취소·오류와 분할된 도식 코드 차단을 검증한다.

- 위치 갱신은 NDJSON과 `X-LearnCraft-Image-Slots: 1`을 함께 요청한 클라이언트에서 활성화한다. 기존 클라이언트는 본문 뒤 이미지 추가 방식을 유지한다. 최종 저장·복사에 사용되는 답변도 본문 내 그림 순서를 유지한다.
