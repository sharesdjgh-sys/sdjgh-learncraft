# 피드백 이미지 저장

현재 이미지 첨부 UI는 기본적으로 숨겨져 있습니다. 텍스트 피드백은 그대로 사용할 수 있으며, 이미지 변환·저장·조회 코드는 유지합니다. 저장소 연결 후 `NEXT_PUBLIC_FEEDBACK_IMAGES_ENABLED=true`를 설정하고 다시 빌드·배포하면 첨부 입력과 안내가 표시됩니다. 이 설정은 화면 노출만 제어하며 기존 첨부 이미지 조회와 API 권한 검사는 유지됩니다.

최대 3장의 PNG/JPEG/WebP를 선택할 수 있습니다. 브라우저에서 긴 변 1,600px, WebP 압축을 적용해 장당 1MB 이하로 전송합니다. 원본은 장당 10MB, 2,400만 화소까지 허용합니다. 서버는 실제 파일을 다시 디코딩하고 WebP로 재인코딩해 메타데이터를 제거합니다. DB에는 파일 경로, 식별자, 가로·세로 크기, 용량만 저장합니다.

## 개발 환경

`BLOB_READ_WRITE_TOKEN`이 없으면 프로젝트의 `.feedback-uploads`에 저장합니다. 이 폴더는 Git에서 제외되며 public 폴더 밖에 있습니다. 폴더를 지우면 개발용 첨부 이미지를 복구할 수 없습니다.

## 운영 환경 연결

1. Vercel 프로젝트의 Storage에서 **Private** Blob 저장소를 만들고 프로젝트에 연결합니다.
2. 서버 환경변수 `BLOB_READ_WRITE_TOKEN`을 설정합니다. `NEXT_PUBLIC_` 접두사를 붙이지 않습니다.
3. 다시 배포합니다. 다른 호스팅에서도 동일한 환경변수로 이 저장소를 이용할 수 있습니다.

운영 모드에서 토큰이 없으면 이미지 첨부 등록은 안내 메시지와 함께 차단합니다. 이미지 없는 피드백은 정상 등록됩니다. 개발용 로컬 파일을 운영 저장소로 자동 이전하지 않습니다.

설정 문서: https://vercel.com/docs/vercel-blob/private-storage

## 접근과 삭제

파일은 로그인된 작성자 또는 같은 학교 관리자만 인증 API를 통해 조회합니다. 저장소 주소와 토큰은 클라이언트에 전달하지 않습니다. 피드백 삭제 시 파일을 먼저 삭제하고 DB 행을 삭제합니다. 파일 삭제가 실패하면 DB 메타데이터를 유지해 재시도할 수 있습니다.

중복 등록 재시도에서 사용하지 않은 파일은 정리합니다. DB 연결 장애로 저장 여부를 확인할 수 없으면 참조 중인 파일을 손상시키지 않도록 보존하고 서버 로그에 요청 ID를 기록합니다. 프로세스 강제 종료 등으로 남은 고아 파일은 저장소 목록과 DB의 images 경로를 대조해 정리해야 합니다.
